# Çalışma sonucu ve güvenli silme dilimi uygulandı

Durum: accepted — 2026-09-13. Kapsam: [spec §8/4](../specs/agentdeck-v0.md). [ADR 0007](0007-slice-1-implementation-boundaries.md)'nin daralttığı iki hükmü (içerik fingerprint'i, kademeli proje silme) ve [ADR 0008](0008-terminal-slice-implementation.md)'in bıraktığı önceki Run seçicisini kapatır.

**Arşiv.** `POST /api/sessions/:id/archive {expectedRunId, stopIfLive}` ve `/unarchive`. Canlı Run veya kalan süreç grubu `stopIfLive:true` olmadan 409 `live_requires_stop` döner; doğrulanmış durdurma başarısızsa arşivlenmez. Arşiv kayda, çalışma kopyasına, branch'e ve terminal görüntülerine dokunmaz. Arşivdeki oturumda restart/launch 409 `session_archived` döner: aktif taramada görünmeyen oturum sessizce canlanmaz. Arşivlenen oturum çalışma alanı taramasında ve kenar çubuğunda gösterilmez, Arşiv filtresiyle bulunur. Terminal grid paneli elle eklendiği için kapatılmaz. Kalan süreç grubunu arayüzün görebilmesi için durum görünümü türetilmiş `remainingProcessGroup` alanını taşır; bu alan diske yazılmaz.

**Diff kapsamları.** `GET /api/sessions/:id/diff?scope=work|uncommitted`. İzole oturumun varsayılanı `work` (base commit'ten çalışma ağacına toplam fark), ortak oturumunki `uncommitted`'dır. Klasör oturumunda her alt depo kendi worktree kaydındaki commit'e göre okunur. Base bilinmiyorsa veya depoda erişilemiyorsa o depo `error` ile kapalıdır; HEAD ile ikame yapılmaz. Okuma 5 sn, 1 MiB patch, 50 takip edilmeyen dosya içeriği ve 10.000 status girişi / 1 MiB ile sınırlıdır; kesilme `patchTruncated`/`statusTruncated` ile işaretlenir. Git hatası artık boş diff'e çevrilmez. Okuma başı ve sonu arasında HEAD değişirse sonuç `stale` işaretlenir. Diff ve branch okuması aynı anda en çok iki Git işi çalıştırır.

**Aynı çalışma kopyasında komut.** `POST /api/sessions/:id/launch` `mode:"command"|"fresh"|"picker"` kabul eder. `resume` 400 `mode_unsupported` (yönetilen kimlik [G2](../specs/agentdeck-v0-validation-gates.md) geçmeden kapalıdır). fresh yalnız argümansız literal CLI, picker yalnız CLI seçicisidir; ikisi de UUID üretmez, kayda `lastLaunch.mode` olarak yazılır. Restart kayıttaki niyeti tekrarlar. Başlangıç Command'ı değişmez. Modun izinli olmayan alanı 400 döner. Sözleşmede olmayan `GET /api/sessions/:id/runs` önceki Run görüntülerini checkpoint dosya adlarından listeler; aynı oturumda mutation sürerken 409 döner, böylece kayda girmemiş Run önceki Run gibi görünmez. İnceleme mevcut WS `run=` yoluyla salt okunurdur.

**Korunan branch'ler.** `GET /api/projects/:id/branches` `refs/heads/agentdeck/` adlarını ve tip OID'lerini 5 sn / proje başına 1000 ref sınırıyla okur. Klasör projesinde her alt depo ayrı okunur. Branch'i gösteren kayıt yoksa `sessionId` null kalır; Git hatası boş listeyle karıştırılmaz.

**İçerik fingerprint'i.** `fingerprint.ts` kaldırılacak çalışma kopyasında geri getirilemeyecek içeriği hash eder: index'teki blob kimlikleri, değişmiş takip edilen dosyalar, takip edilmeyen ve ignored dosyaların içeriği. Ignored klasörler ve iç içe depolar tek status girişi olarak geldiği için içleri dolaşılır. Symlink izlenmez, hedef metni hash edilir. Temiz takip edilen dosyalar branch'te durduğu için okunmaz. Git yolları bayt olarak korunur. Bütçe (5 sn / 10.000 dosya / 128 MiB) bir oturumun bütün worktree'lerine paylaştırılır. Aşım veya okuma hatasında onay üretilmez: 409 `preview_budget_exceeded` / `status_unreadable`; bypass yolu yoktur. `fingerprintScope` izole oturumda `content`, ortak oturumda `dir-identity`'dir.

**Silme sırası.** Session kilidi altında: onayın Run'ı kapsadığı denetlenir (yeni Run durdurulmaz), süreç grubu doğrulanmış biçimde durdurulur, dizin kimliği ve fingerprint yeniden okunur, ancak sonra worktree'ler ve kayıt kaldırılır.

**Kademeli proje silme.** `POST /api/projects/:id/delete-preview` bütün oturumları tek onaya bağlar; bütçe oturumlar arasında paylaşılır ve aşımda oturumları tek tek temizlemek önerilir. `DELETE /api/projects/:id {confirmationToken}` onayı tek kullanımlık tüketir. Onaydan sonra oturum kümesi değiştiyse hiçbir şey yapılmaz. Sonra bütün Session kilitleri alınır, Run'lar denetlenir, gruplar durdurulur ve içerik tek bütçeyle yeniden okunur; değişim 409 `confirmation_stale` ile döner, oturumlar durmuş kalır ve hiçbir şey silinmez. Kaldırma sırayla yapılır; ilk hatada durulur, proje kalır ve `project_delete_partial` silinen ve kalan oturumları listeler. Onay süresi işlemin başında denetlenir; kaldırma sürerken dolması işlemi yarıda kesmez. Oturumu olmayan proje önceki gibi onaysız kaldırılır.

**Arayüz.** Üst çubukta arşivle / durdur ve arşivle / arşivden çıkar, komut çalıştır diyaloğu, yolu kopyala ve Güncel/Önceki Run seçicisi vardır. Her eylemin tek cümlelik açıklaması fare veya klavye odağıyla terminalin üstünde yüzer; terminal boyutu değişmez. Silme onayı tam klasör yolunu, proje silme onayı silinecek bütün izole çalışma kopyalarını listeler. Diff sekmesi "Bu çalışma" / "Commit edilmemiş" seçicisini, kesilme, stale ve Git hatası bildirimlerini gösterir.

Bilinen sınırlar:
- Klasör oturumunda ajanın depo dışına yazdığı dosyalar silinmediği için fingerprint'e girmez; kapsayıcı yerinde kalır ve yetim keşfinde görünür.
- Dış programların onay ile kaldırma arasındaki yazımına dosya sistemi transaction garantisi yoktur.
- Büyük `node_modules` tek bir oturumda bile bütçeyi aşabilir; kullanıcı yerel araçla temizler. Bu denge pilotta sınanır.

Ölçülen (13 Eylül): arşiv durdurması kilidi tutarken silme 409 döner; silme durdurması sürerken arşiv aynı 409'u verir; tam 128 MiB kabul edilir, bir bayt aşım reddedilir; ignored iç içe Git deposunda dosya değişimi fingerprint'i değiştirir.

Doğrulama: `npm test`, `npm run typecheck`, `npm run build`. Derlenmiş arayüz Electron'un Chromium'unda sürüldü: arşiv, arşiv filtresi, branch paneli, komut çalıştırma, önceki Run incelemesi, diff kapsamları ve kademeli proje silme 31 kontrolden geçti, konsol hatası yok. Bu bir duman testidir; G4 kullanıcı kabulü ve gerçek CLI akışı yapılmadı.
